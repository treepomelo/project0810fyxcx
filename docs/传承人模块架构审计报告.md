# fyxcx0810 传承人模块架构审计报告

> 依据《传承人业务域开发规格》第 37 节输出。审计于 2026-08-14 完成。
> 本报告为编码前置产物，先审计、后编码。

## 1. 当前项目架构

- **底座**：Yudao / RuoYi-Vue-Pro 二开（芋道源码 ruoyi-vue-pro）。
- **构建**：Maven 多模块；根 `pom.xml` 版本 `2026.07-jdk8-SNAPSHOT`，Java 1.8，Spring Boot 2.7.18。
- **形态**：单体应用（单 `yudao-server` 空壳容器聚合模块），**非微服务**。
- **激活模块**：`yudao-module-system`、`yudao-module-infra`（根 pom 仅这两者未注释）。
- **未激活但有完整源码**：member、mall(product/promotion/trade/statistics)、im、crm、erp、bpm、pay、mp、report、iot、mes、wms、ai。
- **包名规范**：`cn.iocoder.yudao.module.<模块名>`；激活模块为单 jar（不拆 -api/-biz），`api` 仅作为模块内子包。
- **端口/配置**：`yudao-server` 48080；`application-local.yaml` 指向 MySQL `ruoyi-vue-pro-jdk8`（root/123456）、Redis 127.0.0.1:6379。
- **前端**：`yudao-ui/yudao-ui-admin-vue3`（Vue3+TS+Element Plus，仓库内仅保留 MES 最小骨架，无 package.json）；其余 uniapp/vben/vue2 为 README 占位，指向外部仓库。

## 2. Yudao/RuoYi 版本与模块结构

- 单 jar 业务模块范式（参照 `yudao-module-system`）：`controller/admin|app` + `service` + `dal/dataobject` + `dal/mysql` + `enums`。
- 控制器规范：`@RestController + @RequestMapping("/模块/实体")`，分页返回 `CommonResult<PageResult<T>>`，DTO 转 VO 用 `BeanUtils.toBean`。
- 权限：`@PreAuthorize("@ss.hasPermission('xx:yy:zz')")`。
- DB 层：MyBatis-Plus，DO 继承 `BaseDO`/`TenantBaseDO`，Mapper 继承 `BaseMapperX`，条件用 `LambdaQueryWrapperX`。
- 前端菜单为**动态菜单**（`system_menu` 下发），前端 `component_name` 与菜单 `component_name` 对应。

## 3. 当前用户体系

- **后台管理员**：`system_users`（`AdminUserDO`，system 模块），登录取当前用户 `SecurityFrameworkUtils.getLoginUserId()`。
- **C 端会员**：`yudao-module-member` 的 `member_user`（`MemberUserDO`）——**代码存在但未激活编译，且无建表 SQL**。
- **令牌**：统一 OAuth2，`system_oauth2_access_token`（Redis key `oauth2_access_token:%s`），按 URL 前缀区分用户类型（`/admin-api`→ADMIN、`/app-api`→MEMBER）。
- **关键结论**：当前运行态只有后台用户可用；C 端会员体系需激活 member 模块才能投入使用。

## 4. 当前 IM 能力

- `yudao-module-im` 有**完整 biz 代码**（私聊/群聊/频道、WebSocket、已读游标、消息历史/pull），但：
  - 根 pom 注释，未激活；且**无跨模块 API 门面**（api 包为空占位）。
  - 全部 controller 在 `controller/admin`（**ADMIN 用户态**），无 member 端入口。
  - 私聊**强制好友校验**，无"客服/业务会话/targetType"模式，无 `openChat/createConversation/startSession` 业务入口。
- **结论**：现有 IM 不可直接作为传承人"在线咨询"会话复用。本轮**不开发 IM、不接入 IM**，仅预留 `inheritorId` 业务上下文；待统一 IM 激活后再接入（规格第 5/24 节）。

## 5. 当前 OSS 能力

- `yudao-module-infra`：`/infra/file/upload`（admin）+ `/infra/file/upload`（app，`@PermitAll`）、`/presigned-url`、`/create`。
- 存储抽象 `FileClient`（DB/Local/S3/FTP/SFTP），表 `infra_file` / `infra_file_content` / `infra_file_config`。
- **结论**：可完整复用；传承人头像/作品图/证书图只存 `url`（文件 id），不新建 OSS 体系。

## 6. 当前权限体系

- RBAC：`system_role` / `system_menu` / `system_user_role` / `system_role_menu`，后端 `@ss.hasPermission`。
- C 端 app-api 不做功能权限校验（仅登录态），用 `getLoginUserId()`。
- **结论**：后台管理复用 RBAC，权限按 `inherit:inheritor:*`（遵循当前项目 `<模块>:<实体>:<动作>` 规范）。

## 7. 当前地区体系

- 无地区表；地区树来自框架 `yudao-spring-boot-starter-biz-ip` 内置 area 数据，接口 `GET /system/area/tree`（system 模块 admin+app 双端）。
- `AreaUtils.getArea(Integer id)` / `AreaUtils.format(id)` 可直接解析名称。
- **结论**：复用；传承人只存 `province_code/city_code/district_code`（Integer 地区编号），名称由 AreaUtils 解析。

## 8. 当前关注/收藏体系

- 激活模块内**无统一用户行为体系**（无 FollowDO/FavoriteDO）。
- 未激活 mall 内有 `product_favorite`（仅绑定 ProductSpu）。
- 遗留库 `heritage.favorite` 为泛型 `user_id+type+target_id` 收藏表（见第 9 节），**不属于本代码库运行时**。
- **结论**：在 Yudao 运行态需自建 `inherit_inheritor_follow`（`user_id+inheritor_id` 唯一），与遗留 favorite 语义对齐。

## 9. 当前 inheritor 实现

- 本代码库（fyxcx0810）内：**零 inheritor 代码**，无任何非遗/传承相关 Java/前端/SQL。
- 本地 MySQL 存在遗留库 `heritage`，含 `inheritor` 表（name/phone/id_card/skill_type/portrait/region_code/profile/audit_status/display_status/is_recommend 等）、`heritage_project`、`heritage_level`、`favorite`、`city`、`user`/`admin`。此为**旧平台数据模型**，非本 Yudao 运行库。
- **结论**：在 Yudao 内全新实现传承人域；表设计与遗留 `heritage.inheritor` 语义对齐，便于将来数据迁移（映射见开发报告）。

## 10. 当前 HeritageProject 实现

- 本代码库内**不存在** HeritageProject 模块/代码。
- 遗留 `heritage.heritage_project` 存在（含 category_id/level_code/region_code）。
- **结论**：非遗项目属未来独立模块；本轮只建 `inherit_inheritor_project_relation`（仅存 `project_id`，禁止冗余主数据、禁止跨库 FK），门类筛选链路 `Inheritor → relation → HeritageProject → category` 待 HeritageProject 模块就绪后打通。

## 11. 当前 Product 实现

- `yudao-module-mall/yudao-module-product` 代码完整（`ProductSpuDO`/`ProductSkuDO`/`product_category` 等），但 mall 整链未激活。
- **结论**：不建 `inherit_inheritor_product_relation`（本轮推迟），待 mall 激活后按 ID 关联，禁止复制 SPU/SKU/库存/订单。

## 12. 当前 Service 实现

- **不存在**任何"服务预约/日程/排期"业务模块（全仓库搜索 schedule/booking/预约/排期无业务命中）。
- **结论**：不建 `inherit_inheritor_service_relation`、不建 service/schedule/booking（本轮推迟）；预约体验入口依赖未来 Service 模块。

## 13. 可复用能力

| 能力 | 来源 | 方式 |
| --- | --- | --- |
| 后台用户/权限/RBAC | system | `SecurityFrameworkUtils.getLoginUserId()` + `@ss.hasPermission` |
| C 端会员用户 | member（待激活） | `member_user` + OAuth2 token(userType=MEMBER) |
| 文件/图片上传 | infra | `/infra/file/upload`（admin/app） |
| 地区树 | system+framework-ip | `/system/area/tree`、`AreaUtils` |
| 字典 | system | `system_dict_data`、`DictDataApi` |
| 逻辑删除/租户/分页/缓存/日志 | framework starter | `BaseDO`/`TenantBaseDO`/`BaseMapperX`/`PageResult` |

## 14. 必须新增能力

- 新业务模块 `yudao-module-inherit`（传承人域：主表/资质/作品/项目关系/关注）。
- 激活 `yudao-module-member`（补齐 C 端用户运行时）并补充 member_user 建表 SQL。
- 增量 SQL（建表 + 字典 + 菜单权限）。
- 前端后台页面（列表/详情，admin-vue3 骨架范式）。

## 18. 是否需要新增微服务

**否**。遵循单体架构，新增为普通 Maven 模块 `yudao-module-inherit`，由 `yudao-server` 聚合（规格第 35 节）。

## 19. 是否需要新增 IM

**否**。本轮不开发、不接入 IM（规格第 5 节）：仓库 IM 未激活且为 ADMIN-only、无业务会话模式。传承人详情页预留"在线咨询"入口与 `inheritorId` 上下文，待统一 IM 接入。

## 20. 风险与模块冲突

1. **C 端用户运行时**：member 未激活 → 关注接口依赖的 MEMBER token 无法签发。已通过激活 member + 补充建表 SQL 解决；若激活后编译/运行异常，回退为"关注接口按标准 Yudao member 预留"，并在开发报告中说明。
2. **基础 SQL 不完整**：`ruoyi-vue-pro.sql` 缺 OAuth2/会员/Quartz 表，需从各模块 test resources 的 create_tables.sql 转换补齐。
3. **前端骨架不完整**：admin-vue3 无 package.json/axios 基建，页面按 MES 骨架 + 官方 yudao-ui-admin-vue3 规范编写，需并入完整前端工程后方可运行。
4. **Redis 未运行**：本地 6379 拒绝连接，完整启动冒烟测试受限；以编译通过 + SQL 落库 + 接口文档作为验证基线。
5. **命名冲突**：沿用 Yudao 规范避免与遗留 `heritage.*`（`inheritor`/`favorite`/`city`/`user`）混淆——新表统一 `inherit_` 前缀，不改动遗留库。
