## 一、开发目标与范围

### 1. 目标
在本仓库既有 Yudao 单体现有底座（system / infra）之上，新增「非遗-传承人」完整业务域：**传承人主数据、荣誉/资质、作品、非遗项目关系、用户关注**，同时打通 **管理后台（Admin）** 与 **用户 App（App）** 两条链路，全部复用既有底座能力，不新建任何重复主数据。

### 2. 范围
- 后端：新建独立模块 `yudao-module-inherit`（单体模块，与 system/infra 同级）。
- C 端用户体系：激活既有 `yudao-module-member`，**不新建用户/账号体系**。
- 数据库：新增 5 张 `inherit_` 业务表 + 2 个数据字典 + 非遗管理菜单（id 7000-7034）。
- 前端：admin-vue3 下新增 4 个业务页面 + 4 个 API 模块。
- 明确**不做**：不重复造 IM 聊天/消息/会话/WebSocket；不重复造地区/权限/OSS 上传；不建角色权限表。

### 3. 关键原则落地
| 硬性约束（需求） | 落地方式 |
| --- | --- |
| 不新建用户体系 | 复用 `member_user` + `SecurityFrameworkUtils.getLoginUserId()`；关注表只存 `user_id` |
| 复用既有 IM | 仓库 IM 为后台管理域、未激活、无业务会话模式，**不接入**；详情页「在线咨询」仅保留 `inheritor_id` 入口（预留） |
| 复用地区 | 地区只存 `province_code/city_code/district_code`，名称由 `AreaUtils` 解析 |
| 复用 RBAC | 使用 `@PreAuthorize("@ss.hasPermission('inherit:xxx:yyy')")` 现有体系 |
| 复用 OSS/文件 | 图片字段仅存 URL，上传复用底座文件上传 |
| 跨域关系只存 ID | `inherit_inheritor_project_relation` 只存 `inheritor_id + project_id`（弱关联，无跨模块 FK） |
| 删除级联 | 删除传承人 → 逻辑删除 作品/资质/项目关系/关注 |
| 不重复创建 Inheritor | 先审计确认无继承领域代码后新建，命名带 `inherit_` 前缀与旧 `heritage` 库区分 |

## 二、总体设计

### 4. 模块定位
`yudao-module-inherit` 依赖：system（地区/RBAC）、infra（文件/日志）、框架 starters（mybatis/security/tenant/ip/excel）。

### 5. 分层结构（遵循 Yudao 规范）
```
controller/admin/inheritor       管理后台 API
controller/app/inheritor         用户 App API
service/inheritor                Service 接口 + 实现
dal/dataobject/inheritor         DO（MyBatis-Plus）
dal/mysql/inheritor              Mapper（继承 BaseMapperX）
enums/ErrorCodeConstants         错误码（1_001_000_000 ~ 000_006）
```

### 6. 前后端接口约定
- Admin 前缀：`/admin-api`，返回 `CommonResult`。
- App 前缀：`/app-api`，浏览接口 `@PermitAll`，关注接口要求登录。
- 统一分页 `PageParam`/`PageResult`、统一 Bean 拷贝 `BeanUtils.toBean`。

## 三、数据库设计

### 7. 新增表（MySQL 8，utf8mb4_unicode_ci，均带 tenant_id）
| 表名 | 说明 | 关键约束 |
| --- | --- | --- |
| `inherit_inheritor` | 传承人主表 | 审核/展示/推荐/排序；`idx_audit`、`idx_region` |
| `inherit_inheritor_qualification` | 荣誉/资质 | 类型/级别/颁发机构/证书编号；`idx_inheritor` |
| `inherit_inheritor_work` | 作品 | 图集 `images json`（JacksonTypeHandler）；`idx_inheritor` |
| `inherit_inheritor_project_relation` | 传承人-非遗项目关系 | 唯一键 `uk_inheritor_project(inheritor_id,project_id)` |
| `inherit_inheritor_follow` | 用户关注 | 唯一键 `uk_user_inheritor(user_id,inheritor_id)` |

> 逻辑删除统一 `deleted bit(1)`（@TableLogic）；跨模块不做物理外键。

### 8. 增量 SQL 文件
- `sql/mysql/ruoyi-vue-pro-inherit.sql`：5 表 + 2 字典 + 菜单。
- `sql/mysql/ruoyi-vue-pro-member.sql`：member 模块核心表（member_user 等 6 张），补齐底座缺失的 C 端用户表，并含演示会员（15601691300 / admin123）。
- 已导入本地库 `ruoyi-vue-pro-jdk8`（root/1234）。

### 9. 数据字典
- `inherit_inheritor_level`：国家级/省级/市级/区县级代表性传承人。
- `inherit_qualification_type`：荣誉/资质/代表性传承人身份/获奖/证书。

## 四、代码设计

### 10. DO 设计
- 继承 `TenantBaseDO`（多租户），主键 `id`，`@TableName` 映射。
- `InheritorWorkDO.images` 用 `@TableField(typeHandler = JacksonTypeHandler.class)` + `autoResultMap = true` 存 JSON 图集。
- 审核状态常量：`AUDIT_STATUS_INIT/SUCCESS/FAIL = 0/1/2`。

### 11. Mapper 设计
- 均继承 `BaseMapperX`，用 `LambdaQueryWrapperX`（`likeIfPresent/eqIfPresent`）。
- App 分页强制过滤：`status=ENABLE(0)` + `audit_status=SUCCESS(1)` + `display_status=1` + 关键词（姓名/擅长技艺）。
- 级联删除方法：`deleteByInheritorId`（作品/资质/关系/关注）。

### 12. Service 设计
- `InheritorService`：create/update/delete/get/getPage/updateAudit/getInheritorAppPage/getInheritorList/validateInheritorExists。
- `updateAudit`：通过审核且展示中 → 写 `publishedAt`。
- `deleteInheritor`：级联逻辑删除子表。
- `InheritorFollowService`：关注/取关/是否已关注/关注数/我的关注分页/批量关注数；重复关注与未关注均有错误码。
- 子服务：Qualification / Work / ProjectRelation（含 `uk_inheritor_project` 防重复校验）。

### 13. 错误码（ErrorCodeConstants）
`1_001_000_000` 传承人不存在、`000_001` 姓名重复（预留）、`000_002/003/004/005` 子表不存在/重复等、`000_006` 关注重复/不存在。

### 14. 管理后台 API
| 接口 | 权限 |
| --- | --- |
| `POST /inherit/inheritor/create` | `inherit:inheritor:create` |
| `PUT /inherit/inheritor/update` | `inherit:inheritor:update` |
| `PUT /inherit/inheritor/update-audit` | `inherit:inheritor:audit` |
| `DELETE /inherit/inheritor/delete?id=` | `inherit:inheritor:delete` |
| `GET /inherit/inheritor/get`、`/page` | `inherit:inheritor:query` |
| 荣誉资质 / 作品 / 项目关系 CRUD+分页 | `inherit:inheritor-qualification:*`、`inherit:inheritor-work:*`、`inherit:inheritor-project-relation:*` |

> 管理后台返回地区名称（provinceName/cityName/districtName）与关注数（followCount），避免前端重复解析。

### 15. 用户 App API
| 接口 | 说明 |
| --- | --- |
| `GET /app-api/inherit/inheritor/page` | 传承人分页（关键词/地区/级别），`@PermitAll` |
| `GET /app-api/inherit/inheritor/get?id=` | 详情（含 isFollowed、followCount），`@PermitAll` |
| `GET /app-api/inherit/inheritor/works`、`/qualifications`、`/projects` | 关联数据，`@PermitAll` |
| `POST /app-api/inherit/inheritor-follow/create`、`DELETE /delete`、`GET /get`、`GET /page` | 关注/取关/状态/我的关注，**要求登录** |

### 16. 菜单与权限（system_menu，id 7000-7034）
- 顶级目录「非遗管理」`/inherit`（sort=15）→ 传承人管理 / 荣誉资质管理 / 作品管理 / 非遗项目关系。
- 每个业务菜单挂 查询/创建/更新/删除 按钮权限，传承人另挂「审核」按钮权限。

### 17. 前端（admin-vue3）
- `src/api/inherit/inheritor/index.ts`（含 AreaApi 地区树）
- `src/api/inherit/inheritorQualification|inheritorWork|inheritorProjectRelation/index.ts`
- `src/views/inherit/inheritor/index.vue` + `components/InheritorForm.vue`（地区级联、图片上传、推荐开关）
- 荣誉资质/作品/关系 各列表页 + 表单对话框
- 遵循 yudao-ui-admin-vue3 规范（ContentWrap / Icon / Pagination / useDict / v-hasPermi / FileUpload）。

## 五、复用与延期说明

### 18. 已复用能力清单
1. 用户体系：`member_user`（激活 member 模块）。
2. 权限：system RBAC `@ss.hasPermission`。
3. 地区：`AreaUtils` / `/system/area/tree`。
4. 文件上传：复用底座文件上传，字段仅存 URL。
5. 分页/拷贝/逻辑删除：框架通用能力。
6. 错误码/异常：`ServiceExceptionUtil`。

### 19. 明确延期项（不阻塞本模块）
- **非遗项目主数据（HeritageProject）**：本模块仅以 `project_id` 弱关联；门类筛选链路在项目模块就绪后接入。
- **商品/服务关系**：`inherit_inheritor_product_relation`、`inherit_inheritor_service_relation` 暂缓（mall/service 模块未激活，无关系来源）。
- **IM 在线咨询**：不建 IM，仅保留入口字段。
- **支付/预约体验**：依赖 Service 模块，仅预留。
- **旧 `heritage` 库迁移**：不触碰旧库，本模块新表独立、语义对齐，后续可迁移。
