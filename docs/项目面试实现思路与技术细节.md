## 一、项目一句话

在开源 Yudao（ruoyi-vue-pro）单体后端基础上二次开发，新增**非遗-传承人业务域**（`yudao-module-inherit`）：提供传承人档案、作品、荣誉资质、非遗项目关联、C 端用户关注 5 类业务，管理后台（admin-api）负责录入/审核/上下架，App 端（app-api）负责公开浏览，并通过**公开可见性过滤**保证未审核/未展示/停用的数据不泄露给 C 端。

- 单模块独立开发：inherit 模块内部自洽（Controller/Service/Mapper/DO/VO），不跨模块调服务；
- 与 member 的唯一关系是**弱关联**：`inherit_inheritor_follow.user_id` 只存用户 id，不 join member 表；
- 与「非遗项目」模块的关系同理：`inherit_inheritor_project_relation.project_id` 弱关联（目标项目模块尚未开发）。

## 三、传承人业务域实现

### 3.1 数据模型（5 张表，SQL 见 sql/mysql/ruoyi-vue-pro-inherit.sql）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `inherit_inheritor` | name/avatar/gender/specialty/level/introduction/profile | 主表。**三态可见控制**：status（通用启停）、audit_status（审核 0/1/2）、display_status（是否展示） |
| `inherit_inheritor_work` | inheritor_id/name/images/description/year/material/technique | 作品，`images` 存 JSON 字符串（JacksonTypeHandler） |

> 所有表带 tenant_id（多租户）、creator/updater/create_time/update_time/deleted（@TableLogic 逻辑删除）。

### 3.2 接口划分

| 端 | 接口 | 认证 | 说明 |
| --- | --- | --- | --- |
| admin | `/admin-api/inherit/inheritor/**` | Bearer token | 分页/创建/更新/删除/**审核**/上下架 |

## 四、复用底座（改造成本极低的来源）

### 4.1 RBAC 权限
复用 `yudao-module-system`：用户在 `system_user`，角色 `system_role`，菜单 `system_menu`（含 `permission` 字符串）。管理后台接口加 `@PreAuthorize("@ss.hasPermission('inherit:inheritor:query')")`，前端按钮按权限控制。本模块在菜单 SQL 里预置了菜单 id 7000-7034 及权限码。

### 4.2 多租户
`yudao.tenant.enable=true`，MyBatis 拦截器自动在 SQL 追加 `tenant_id` 条件。请求带 `tenant-id: 1` 头（YudaoTokenFilter 解析）。App 公开接口 `@PermitAll` 仍需租户头，因为公开数据也按租户隔离。

### 4.3 逻辑删除 & 审计字段
`BaseDO` 内置 `deleted/creator/updater/create_time/update_time`，`@TableLogic` 自动拼 `deleted=0`；`@TableField(fill=...)` 自动填充审计字段。

### 4.4 通用能力
- 统一异常：`ServiceExceptionUtil.exception(ErrorCode)` → `ErrorCode(1_001_000_000, "传承人不存在")`，全局异常处理器转成 `code/message/data` 结构；
- 统一返回：`CommonResult<T>`，code=0 成功；
- 分页：`PageParam + PageResult` + `LambdaQueryWrapperX` / `selectPage`;
- 字典：`@DictFormat` 解析 `inherit_` 字典；
- 文件上传、SMS、通知：走 infra/system 既有能力，本模块未新增依赖。

## 五、核心亮点：App 公开可见性设计（P1 修复，面试重点）

### 5.1 问题背景
二次验收发现：App 详情接口 `getInheritor` 只做了 `selectById`（仅过滤 `deleted=0`），导致**未审核、审核通过未展示、已停用**的传承人只要知道 id 就能拿到全部资料；作品/资质/项目关系子接口也**未先校验父传承人是否公开**，且子表 `selectListByInheritorId` 无 status 过滤 → 停用子数据同样泄露。

### 5.2 判定模型
公开可见 = `status=ENABLE(0) AND audit_status=SUCCESS(1) AND display_status=1 AND deleted=0`（单一判定点落在 Mapper）。

```java
// InheritorMapper.selectPublicInheritor —— 4 个等值条件超过 BaseMapperX.selectOne 的
// 3 参 (SFunction,Object) 重载上限，故用 LambdaQueryWrapperX 形式
default InheritorDO selectPublicInheritor(Long id) {
    return selectOne(new LambdaQueryWrapperX<InheritorDO>()
            .eq(InheritorDO::getId, id)
            .eq(InheritorDO::getStatus, CommonStatusEnum.ENABLE.getStatus())
            .eq(InheritorDO::getAuditStatus, InheritorDO.AUDIT_STATUS_SUCCESS)
            .eq(InheritorDO::getDisplayStatus, 1)); // deleted=0 由 @TableLogic 自动追加
}
```

### 5.3 分层落地
- **Service 新增两个 App 专用方法**：`getPublicInheritor(id)`（不可见返回 null，给子表门控用）、`validateInheritorPublicExists(id)`（不可见抛 `INHERITOR_NOT_EXISTS`，给详情用）；
- **详情接口**：Controller 改用 `validateInheritorPublicExists`；
- **子数据门控**：`getWorkListByInheritorId` 等先 `if (getPublicInheritor(inheritorId) == null) return new ArrayList<>();`，父不可见则返回空列表，不泄露子数据；
- **子表只返回启用**：`selectListByInheritorId` 追加 `.eq(status, ENABLE)`；经全仓 grep 确认该方法仅被 App 链路调用，管理后台走 `selectPage` 不受影响。

### 5.4 判定矩阵

| 场景 | App 详情 | App works/qualifications/projects |
| --- | --- | --- |
| ENABLE+SUCCESS+展示+未删 | ✅ 返回 | ✅ 返回（子表仅 ENABLE） |
| 未审核 / 未展示 / 停用 / 已删除 | ❌ code=1001000000 | ❌ 空列表 |
| 管理后台 get/page | ✅ 不受影响 | ✅ 不受影响 |

### 5.5 测试与验证
- 12 个 Service 单测（H2 MODE=MYSQL）：覆盖详情 5 态 + 管理后台不受影响 + 三子表门控与子表停用过滤；
- 12/12 HTTP 冒烟（`smoke_inherit_p1.sh`）全过；
- **零 DDL 变更、零新增主依赖、零跨模块调用**——纯查询层过滤，管理后台行为不变。

> 面试话术：用「单一判定点 + 分层门控」避免在多处重复写过滤条件；新增的公开判定不影响管理后台既有链路，改造成本低、回归风险小。

## 六、关键决策与取舍（技术细节/避坑）

1. **单模块边界**：inherit 作为一个独立 module 开发，内部完成全部 CRUD/审核/门控，不跨模块调服务，与 member/项目仅弱关联。理由：目标项目模块（HeritageProject）尚未开发，避免现在耦合未来返工。
2. **公开过滤放哪一层**：判定 SQL 放 Mapper（单一数据源真相），门控放 Service（保证管理后台/其他调用方不被误伤），Controller 保持薄封装。
3. **`BaseMapperX.selectOne` 3 参上限**：4 条件等值查询必须改用 `LambdaQueryWrapperX`，否则编译不过。
4. **H2 单元测试两大坑**：
   - `year` 是 H2 2.x 保留字 → JDBC URL 加 `NON_KEYWORDS=value,YEAR`；
   - Podam 给非 status/type 结尾的 tinyint 字段生成超范围 int → 测试 DDL 将 gender/is_recommend 放宽为 int；
   - 跑单测必须 `-pl yudao-module-inherit -am test`（reactor 先建上游 SNAPSHOT 模块），且 surefire-junit-platform provider 本地仓库缺失需联网下载。
5. **Maven 兼容性**：flatten-maven-plugin 1.7.2 与本机 Maven 3.6.1 不兼容 → 项目内置 3.8.8，构建统一 `-Dflatten.skip=true -Dflatten.updatePomFile=false`。
6. **git-bash 下 curl 中文**：终端以 GBK 发送导致 Jackson `Invalid UTF-8` → 中文入参写 UTF-8 文件 + `--data-binary @file`。
7. **多租户头**：admin-api 登录/所有接口都要 `tenant-id: 1`；App 公开接口虽 `@PermitAll` 也要租户头（数据按租户隔离）。
