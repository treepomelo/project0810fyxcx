## 3. Yudao/RuoYi 底座复用情况

### 用户
- **完全复用**。关注功能链路：App 登录 → OAuth2 token → `/app-api` 上下文 `SecurityFrameworkUtils.getLoginUserId()` → 得到 **member_user.id** → 写入 `inherit_inheritor_follow.user_id`。
- `yudao-module-inherit/pom.xml` **未依赖 member 模块**，也未注入任何 MemberMapper/UserMapper —— 模块只消费登录态的 userId，不直连任何用户表。
- `inherit_inheritor_follow.user_id` 注释明确为 `member_user.id`；无第二套用户/账号体系。
- `ruoyi-vue-pro-member.sql` 补齐的是 **Yudao 官方 yudao-module-member 的标准表**（member_user/config/tag/level/group/address 共 6 张，与模块内 DO 一一对应），属于「激活既有 C 端用户体系」，而非临时造表。其中演示会员（15601691300/admin123）为**显式标注的种子数据**，仅用于本地联调。

### IM
- 未依赖（pom 无 im 依赖）、未自行实现（无任何 chat/message/websocket 代码）。
- 详情页「在线咨询」仅以方案层面保留入口语义，代码中无 IM 调用。
- **未来接入建议**：HeritageProject/IM 模块就绪后，通过独立「咨询服务」子域或集成 yudao-module-im（若启用）实现，与传承人模块解耦，仅由前端跳转传递 `inheritor_id`。

### OSS
- 未重复建设。avatar/cover/作品图集仅存 URL 字符串，上传走底座文件上传/OSS。

### 权限
- 完全复用 system RBAC。全部接口使用 `@PreAuthorize("@ss.hasPermission('inherit:xxx:yyy')")`，无自定义权限/菜单实现。

### 地区
- 复用 `yudao-spring-boot-starter-biz-ip` 的 `AreaUtils.getArea()` 解析省/市/区名称；数据仅存 3 个整数编号。

### Redis
- 模块自身**零 Redis 使用**（无 RedisTemplate/Redisson/@Cacheable）。Redis 仅是底座框架（登录/oauth2/监控）的运行依赖，非本模块问题。

### 收藏/关注
- 自行实现 follow 表（属传承人业务域，合理）。数据模型与底座无重复（底座无通用收藏抽象；Yudao 的 mall 关注在 mall 模块，本模块不依赖 mall）。

## 6. App 端审查

### 分页可见性（✅ 正确）
`InheritorMapper.selectAppPage` 强制过滤：
```
status = ENABLE(0)  AND  audit_status = SUCCESS(1)  AND  display_status = 1
```
仅公开已启用 + 已审核 + 展示中的传承人；`deleted` 由 `@TableLogic` 自动排除。

### 详情/子列表可见性（❌ P1 —— 存在泄漏）
- `GET /app-api/inherit/inheritor/get?id=` 调用 `validateInheritorExists(id)` → 仅 `selectById`（自动过滤 deleted），**未过滤 audit_status / display_status / status**。
  - **未审核**（audit_status=0）：可被按 id 直达 ✅❌ 泄漏
  - **已下架**（display_status=0）：可被按 id 直达 ✅❌ 泄漏
  - **已停用**（status=1）：可被按 id 直达 ✅❌ 泄漏
  - **已删除**（deleted=1）：被 @TableLogic 排除 ✅ 正确
- `/works`、`/qualifications`、`/projects`：a) 不校验父传承人是否公开；b) `selectListByInheritorId` 不过滤子记录 `status`（已停用的作品/资质仍会返回）。

**修复方向（下期实施）**：App 侧统一走「可见性校验」——详情先按公开条件查询（`status=ENABLE + audit=SUCCESS + display=1`），命中才返回；子列表接口先校验父传承人公开，再按 `status=ENABLE` 过滤子记录。

### PII 隐私（✅ 正确）
App 各 RespVO（AppInheritorRespVO/DetailRespVO/Work/Qualification/ProjectRelation）**不含** `idCard`、`phone`。身份证号/电话仅存在于 Admin VO（InheritorRespVO/SaveReqVO）。

### 关注功能（✅ 正确）
全部要求登录；userId 取自登录态（member_user.id）；重复关注/未关注有错误码（1001000005/000006）；防重复有唯一键兜底。
