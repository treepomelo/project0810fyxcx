## 一、修改前问题（P1 根因）

二次验收定位到 **App 公开详情与关联子数据接口存在未审核/未展示/停用数据泄露**：

1. **详情接口** `GET /app-api/inherit/inheritor/get?id=`
   `AppInheritorController.getInheritor` 只调用 `inheritorService.validateInheritorExists(id)`，内部为 `selectById`（仅靠 `@TableLogic` 过滤 `deleted=0`）。
   → 未审核、已审核但未展示、已停用的传承人，只要知道 id 就能通过公开详情接口拿到全部资料。

2. **关联子数据接口** `GET /app-api/inherit/inheritor/works|qualifications|projects?id=`
   三个接口直接调用 `xxxService.getXxxListByInheritorId`：
   - 未先校验父传承人是否公开 → 父不可见时仍返回其子数据；
   - 作品/资质的 `selectListByInheritorId` 无 `status` 过滤 → 停用子数据也返回（项目关系表无 status 字段，仅受父门控影响）。

管理后台不受影响（验收结论 P1 仅 App 侧），故本次修复全部落在 App 链路。

## 三、修改方法（关键实现）

### 1. 公开可见判定 SQL（Mapper 层，单一判定点）

`InheritorMapper.selectPublicInheritor(Long id)`：

```java
default InheritorDO selectPublicInheritor(Long id) {
    return selectOne(new LambdaQueryWrapperX<InheritorDO>()
            .eq(InheritorDO::getId, id)
            .eq(InheritorDO::getStatus, CommonStatusEnum.ENABLE.getStatus())
            .eq(InheritorDO::getAuditStatus, InheritorDO.AUDIT_STATUS_SUCCESS)
            .eq(InheritorDO::getDisplayStatus, 1)); // deleted=0 由 @TableLogic 自动追加
}
```

> 4 个等值条件超过 `BaseMapperX.selectOne` 的 3 参（SFunction, Object）重载上限，故采用 wrapper 形式（已在 BaseMapperX 源码验证）。

### 2. Service 层新增两方法（App 专用）

```java
InheritorDO getPublicInheritor(Long id);          // 不可见返回 null（子表门控用）
InheritorDO validateInheritorPublicExists(Long id); // 不可见抛 INHERITOR_NOT_EXISTS（详情用）
```

`validateInheritorPublicExists` 复用 `INHERITOR_NOT_EXISTS`（1_001_000_000「传承人不存在」），未新增错误码。

### 3. 详情接口（Controller）

```java
InheritorDO inheritor = inheritorService.validateInheritorPublicExists(id);
```

### 4. 子数据门控（App 专用 Service 方法，管理后台不受影响）

```java
public List<InheritorWorkDO> getWorkListByInheritorId(Long inheritorId) {
    if (inheritorService.getPublicInheritor(inheritorId) == null) {
        return new ArrayList<>();   // 父不可见 → 空列表，不泄露子数据
    }
    return workMapper.selectListByInheritorId(inheritorId); // 已追加 status=ENABLE
}
```

### 5. 子表只返回启用数据（Mapper）

`InheritorWorkMapper.selectListByInheritorId` / `InheritorQualificationMapper.selectListByInheritorId`
追加 `.eq(xxxDO::getStatus, CommonStatusEnum.ENABLE.getStatus())`。
两方法经全仓 grep 确认仅被 App 链路调用（管理后台走 `selectPage`），故不影响管理后台。

## 七、遗留与说明

- 修复思路遵循现有 `Mapper → Service → Controller` 分层与 `ServiceExceptionUtil` 异常规范；
- App 详情错误沿用既有错误码 `INHERITOR_NOT_EXISTS`，未新增；
- 「我的关注」列表（AppInheritorFollowController，要求登录）仍按登录用户视角返回其关注记录，未纳入本次公开过滤范围（属后续评审项）；
- 测试环境提示（已记入项目 memory）：H2 2.x 中 `year` 为保留字需 `NON_KEYWORDS=value,YEAR`；Podam 对非 status/type 结尾的 tinyint 字段生成超范围 int，测试 DDL 将 gender/is_recommend 放宽为 int；本地跑单测需 `-pl ... -am test`（reactor 建上游模块）且 surefire provider 需联网下载。
